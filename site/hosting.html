Hosting and operations

Static content.
A serverless conversation.

Concourse separates the publication, access policy, and collaboration runtime. Keep shared infrastructure in the estate that already owns it.

Cloudflare: the first implementation.

Pages serves static content. Access provides managed sign-in. A Worker validates identity and membership for each API request; D1 stores append-only comments and private feedback. Worker alternate public origins are disabled.

The small Terraform module manages Pages, its domain, DNS, Access policy, and database lifetime. Wrangler manages Worker code, bindings, and exact API routes. These tools have separate ownership, so application releases do not recreate infrastructure.

Prepare, inspect, deploy.

bun run check
bun run test:workerd
bun run build:site
bun run cloudflare:prepare INSTALLATION_PROFILE NEW_RELEASE_DIRECTORY
# Review the artifact, configuration, SQL and printed digest.
# Initialize storage only through a separately approved operation.
bun run cloudflare:deploy RELEASE_DIRECTORY --approve REVIEWED_DIGEST

The preparer works offline. Deployment verifies the packaged bytes and pinned toolchain; it does not apply SQL or publish static files. Publish the reviewed dist/site/ separately to the configured Pages project. Keep real installation identifiers and credentials in the consuming environment.

Use the deployment procedure for infrastructure review, initialization, and admission checks. No cloud resources are created by the site build.

Public documentation, protected participation.

The initial installation policy is public reading with Access protecting only /__concourse. Comments require site membership; feedback reads require an additional maintainer assignment. A private publication instead protects the complete content directory on every origin.

Configure the Concourse API route on the custom hostname only. Pages previews may serve public documentation; they must not become alternate routes into private collaboration. Always verify deployed production, preview, asset and API URLs.

The admin UI shares the backend.

The maintainer workspace runs at /__concourse/admin/. Its shell, assets, searches, counts, and review commands require authorization. The Worker embeds the UI assets, so it needs no separate frontend host. D1 stores canonical messages and review history; search indexes and current review state are rebuildable.

When upgrading from 0.1.x, apply all pending migrations through 0003_management.sql before deploying the new Worker. Configure maintainers for feedback and moderators for discussions. Follow the workspace guide for screenshots and reviewer steps.

Batten on Databricks Apps.

A Batten collaboration plugin and a separate volume-backed static-publication plugin are required future hosting profiles. They are not implemented by the current Cloudflare package. Identity propagation, volume access, and backend storage semantics need their own qualification.

Know the current boundaries.

The native API supports immutable comments and replies, private feedback, and a protected maintainer workspace. Feedback maintainers can triage reports; discussion moderators can resolve or reopen threads. A new reply reopens a resolved thread. Comment editing, hiding, notifications, and UMF action execution are not implemented. Data retention, deletion, export, and recovery policies must be agreed for each installation; local tests are not evidence of production recovery.
